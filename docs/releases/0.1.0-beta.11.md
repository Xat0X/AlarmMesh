# AlarmMesh 0.1.0-beta.11

Phone notification settings now show receiver availability, message previews and clearer route diagnostics. Refreshing receivers preserves newer unsent choices and never replaces a reopened form or an active confirmation with a late response.

Test confirmations are bound to the current recipient and message context. Lost test replies are correlated by request ID without automatic replay. An AlarmMesh timeout is shown as an unknown outcome; an explicit provider failure remains a failure. Home Assistant accepting a request does not prove delivery to a phone.

Validation: 555 backend tests and 99 frontend tests passed, plus Ruff, formatting, hassfest, PowerShell, Compose and isolated compatibility checks on HA 2026.10.4 and 2026.11.1. The complete mock notification chain and eight UI combinations were checked. The original real-phone delivery complaint is not yet proven resolved: no production installation, real phone or detector was operated.

Linked sounding and new automatic functions default off. Existing explicit settings are preserved when updating.

Back up Home Assistant, enable AlarmMesh pre-releases in your installer, select 0.1.0-beta.11 and restart when prompted. For manual installation, extract alarmmesh.zip into custom_components/alarmmesh and restart. Restore the pre-update backup to roll back.

For your separate phone check, open Settings > Configure notifications, verify the intended receiver is available, and request a single explicitly confirmed test notification. Automatic incident notifications can remain off for this check. If nothing arrives, note the displayed request status and time; do not use a smoke alarm to test phone delivery.
