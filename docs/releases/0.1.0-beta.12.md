# AlarmMesh 0.1.0-beta.12

## Critical phone alerts and simpler setup

Configure an explicit smoke-alert profile for each iPhone or Android phone, with
platform-specific sound options and permission help. Preview, confirmed test and
incident delivery share the same validated plan. Existing ordinary notification
settings are preserved; recovery, maintenance and reminders stay noncritical.

Settings are organized around recognizable tasks, with clearer Dutch and English
labels and simpler phone/group forms. After an interrupted save, check the choices
actually stored without resending. Further edits no longer falsely appear saved.

## Installing and testing

Back up Home Assistant before updating. Enable pre-releases in your AlarmMesh
installer and select **0.1.0-beta.12**, then restart when prompted. For manual
installation, extract `alarmmesh.zip` into `custom_components/alarmmesh` and restart.
The ZIP contains the integration files at its root.

**Rollback requires the pre-update backup:** beta.11 does not understand the new
phone-profile fields. Do not simply install older code over the updated storage.

Open **Settings > Phone alerts** and review each intended phone. Critical alerts
require an explicit choice. iPhone requires critical-alert permission; Android
requires checking its alarm channel, alarm volume and Do Not Disturb settings.
Android's immediate-delivery profile does not queue an unreachable phone's alert
for later. Imported iPhone sounds must already exist on that phone.

Saving and viewing a preview send nothing. A separate, explicitly confirmed test
notification can make sound. Home Assistant accepting the request does not prove
phone delivery or audible sound. See [phone setup and limits](https://github.com/Xat0X/AlarmMesh/blob/0.1.0-beta.12/docs/phone-alerts.md).

Linked sounding and new automatic functions remain **off by default**. Existing
explicit settings are preserved. Updating does not authorize or trigger a test.

## Validation and limits

Local review passed 586 backend tests, 108 frontend tests, lint/format, hassfest,
PowerShell/Compose and isolated HA 2026.10.4/2026.11.1 compatibility checks. Eight
language/theme/phone-tablet combinations were inspected. Mock flows cover mixed
critical profiles, errors, timeouts, lost replies and reconnect without duplicates.

Only isolated simulated phones and sources were used. Actual audible delivery,
phone permissions and physical detector operation remain untested. No production
installation or real phone/detector was operated while preparing this release.
