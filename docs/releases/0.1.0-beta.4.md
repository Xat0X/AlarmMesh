# AlarmMesh 0.1.0-beta.4 — Incident actions and self-tests

Test release with optional linked sounders, phone notifications, ordered incident
scripts and capability-gated built-in self-tests, with improved mobile dialogs.

## Install without activating devices

1. Create a Home Assistant backup and keep its recovery information privately.
2. Before updating, switch off **Sound together / Samen laten afgaan** in every
   group. Existing explicitly enabled settings are preserved, not silently reset.
   Leave automatic notifications and script actions disabled during review.
3. In Marketplace/HACS, enable pre-release versions and select **0.1.0-beta.4**.
   Install, restart Home Assistant and refresh the browser.
4. Verify source selection, names, rooms and groups. New linking and notification
   automation defaults to off. Do not start a self-test or enable outputs as part
   of the installation check.

Minimum Home Assistant: **2026.10.4**. Tested exact versions: **2026.10.4** and
**2026.11.1**. Installation uses the normal repository integration-folder route.
The attached `alarmmesh.zip` is an integration-root archive for manual installation
into `custom_components/alarmmesh/`, not a replacement installer mechanism.

Group storage now includes incident origins and action bindings. For rollback,
restore the pre-update backup together with its matching integration version;
replacing files alone does not undo storage changes.

## Included

- Separate incident sources and explicit sounder targets for groups, retaining
  provider/model validation, deduplication and the Bosch broadcast safeguard.
- Companion phone recipients, message previews and separately confirmed test
  requests. No actual phone delivery was performed during validation.
- Ordered HA scripts for incident start and explicitly confirmed recovery,
  with separate receipts, failure isolation and no automatic replay after reload.
- Self-test request ownership, deadlines and cancellation safeguards. Supported
  routes remain capability-gated; missing or interrupted results stay unknown.
  A command being accepted does not establish that a detector passed its test.
- EN/NL setup text, incident details, preserved offline drafts, clearer exact-target
  confirmations and improved phone/tablet layout and icon alignment.

## Validation and limits

Local checks passed: **429 backend tests**, **43 frontend tests**, Ruff, formatting,
hassfest, PowerShell and Compose. Each tested HA version passed **24 runtime and
16 driver checks**. Simulator UI checks covered group actions, incident start,
outage/recovery, failure isolation, self-test activity/timeout/explicit results,
confirmation feedback and reconnect draft retention. See
[the visual review](../visual-flow-review.md) for exact coverage and limitations.
Hosted checks must also pass for the exact release commit before publication.

No real detector, siren, phone or production HA installation was operated.
Physical smoke detection, audible alarm, device self-test and phone delivery
remain unverified. HA acceptance is not proof of physical execution. This beta
does not replace independent smoke alarms or a certified fire alarm system.
