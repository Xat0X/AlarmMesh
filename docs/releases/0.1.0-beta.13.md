# AlarmMesh 0.1.0-beta.13

## My alarm settings and phone test observations

View the existing alarm route for each detector in **My alarm settings**: groups,
shared sounding targets, phones, scripts and relevant problem help. Viewing and
refreshing this overview send nothing.

Record whether an exact phone test was received and heard, separately. These are
user observations, not automatic delivery receipts. History remains available;
changed phone profiles or identities make earlier observations historical. Simulated
observations are explicitly marked and do not establish physical acceptance.

Review changes before saving phone or group settings. After a lost save response,
check the choices actually stored without resending. Further unsaved edits remain
recognizable. Test request IDs cannot dispatch a second test after reload. Recorded
incident events remain distinct from current smoke status.

## Installing and testing

Back up Home Assistant before updating. Enable pre-releases in your installer,
select **0.1.0-beta.13** and restart when prompted. For manual installation, extract
`alarmmesh.zip` into `custom_components/alarmmesh` and restart. The ZIP has integration
files at its root. Restore the pre-update backup when rolling back; older releases
may not understand newer stored fields or preserve test history.

Linked sounding and new automatic functions remain **off by default**. Existing
explicit choices are preserved. Updating, saving and viewing routes send no tests.
A separately confirmed phone test can make sound. Review each phone's permissions,
sound and critical-alert settings before testing. See [phone setup](https://github.com/Xat0X/AlarmMesh/blob/0.1.0-beta.13/docs/phone-alerts.md).

## Validation and limits

Independent local review passed 602 backend tests, 117 frontend tests, Ruff/format,
hassfest, PowerShell/Compose and simulated HA 2026.10.4/2026.11.1 compatibility.
Eight language/theme/phone-tablet combinations were rendered and inspected.
Lost-response tests used actual simulator saves followed by injected response loss
and browser offline/reconnect. A full simulator restart preserved settings and
phone-test history without replaying output. Two local packages were identical.
The 79 status tests and status calculation are unchanged.

Only isolated simulated sources and phones were used in this review. The user's
successful iPhone critical-alert test is separate user-reported evidence, not a
claim about all phones. Physical detector operation and audible delivery were not
tested by the agent. No production installation, real phone or detector was operated.
