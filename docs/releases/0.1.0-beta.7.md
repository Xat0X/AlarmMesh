# AlarmMesh 0.1.0-beta.7 — Activity, reminders and easier organization

Beta test release with bounded activity history, optional check reminders,
combined detector filters and organizational group copies. Includes the reviewed
reminder confirmation, wording, copy-field and activity-result corrections.
The HTTP/self-test request correction from beta.6 remains included.

## Install with outputs disabled

1. Make a Home Assistant backup and keep its recovery information privately.
2. Before updating, turn off **Sound together / Samen laten afgaan** for any
   previously enabled group. Leave notifications, maintenance messages, automatic
   scripts and reminders off during installation review. Existing explicit
   opt-ins are preserved; updating does not silently switch them off.
3. Enable pre-releases in HACS/Marketplace and choose **0.1.0-beta.7**.
4. Install, restart Home Assistant and fully refresh the browser. New groups,
   linking and new automatic features remain **off by default**.
5. Review **Activity**, **Maintenance**, detector filters and **Copy group**.
   Do not start physical self-tests or enable sounder/phone/script actions during
   this installation review. The release process did not operate live devices.

The attached `alarmmesh.zip` contains the integration root. For a manual install,
extract it into `custom_components/alarmmesh/`, not the HA configuration root.
Minimum HA remains **2026.10.4**; exact compatibility checks cover **2026.10.4**
and **2026.11.1**. Other HA versions and physical devices are not implied tested.

For rollback, restore the pre-update backup with its matching integration version.
Replacing code alone does not reverse storage changes. This beta adds separate
versioned activity/reminder stores; do not edit receipts to force another attempt.

## Changes

- **Activity:** locally observed transitions and request states, correlations,
  filters and detail links; bounded to 30 days/1,000 events. Quiet startup does not
  invent history. Incomplete history is reported. HA acceptance remains separate
  from physical sound, phone delivery or a device self-test result.
- **Check reminders:** separately enabled, chosen detector/Companion recipient,
  calendar date at 09:00 in the HA time zone, later/handled and optional repeat
  preferences. These never start a self-test or claim test success. Durable
  one-attempt receipts, quiet restart and smoke priority prevent automatic replay.
- **Organization:** combined detector filters, member search/counts and group
  copying with explicit review. Copies receive no linked-sounder permissions,
  target bindings or scripts. The original group is retained.
- **Usability:** dedicated EN/NL reminder/search labels, confirmation of enabled
  state and repeat interval, styled copy-name field and explicit device-test
  wording in result filters. Four frontend regressions added during review.

## Evidence and limits

Final pre-release functional validation: **508 backend + 66 frontend tests PASS**,
Ruff/format, hassfest, PowerShell, Compose and cleanup PASS. Each exact HA version
passed **29 runtime + 16 isolated provider checks**. The 37 product files matched
the full validated source export before the release-version metadata change.
Release packaging is rebuilt from the release commit; its own hash is attached.

Actual screenshots of reminder/copy/source-event dialogs were inspected in all
eight NL/EN × light/dark × phone/tablet combinations (24 images). Mock smoke and
recovery, filter/detail return, disabled reminder save/later/handled, safe copy and
cleanup were exercised. This is browser emulation, not physical phone/tablet or
detector acceptance. No actual detector, phone or external script was operated.

An offline draft remained visible and could not be submitted. A complete HA
restart caused the browser to reload and discard the unsaved draft. Save settings
before a restart; durable draft preservation across page reload is not provided.
