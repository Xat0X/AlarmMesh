# AlarmMesh 0.1.0-beta.5 — Setup guidance and maintenance

Test release focused on easier configuration, clear maintenance information and
readable incident details. Linking remains off by default. Existing explicit
opt-ins are preserved: disable linked sounding and other automatic outputs before
an installation-only review. No live Home Assistant, detector or phone was operated
when preparing this release.

## Install on your Home Assistant

1. Create a Home Assistant backup first and retain its recovery information privately.
2. If you previously enabled linked sounding, switch it off in every group before
   updating. Leave automatic notifications and incident scripts off during review.
3. In Marketplace/HACS, enable pre-release versions and select **0.1.0-beta.5**.
4. Install, restart Home Assistant and fully refresh the browser to load the new UI.
5. Check your selected detectors, groups and names. Open **Set up and check /
   Instellen en controleren**, **Maintenance / Onderhoud** and **Incident details /
   Incidentdetails**. These views do not require operating a real detector.

The existing repository integration-folder installer route is unchanged. The
attached `alarmmesh.zip` contains integration-root files for manual extraction
into `custom_components/alarmmesh/`, not the Home Assistant configuration root.
Minimum HA remains **2026.10.4**; exact tested versions are **2026.10.4** and
**2026.11.1**. Other versions are not implied tested.

For recovery, restore the pre-update backup with its matching AlarmMesh version.
Replacing integration files alone does not undo configuration/storage changes
introduced by previous betas. No production rollback was performed in this review.

## Improvements

- Seven configuration-derived setup steps, separating configured, optional-off,
  unsupported, unknown and attention states. No general finish button enables outputs.
- Maintenance reports for proven same-device battery/fault information, unavailable
  sources, missing rooms and changed assignments. Missing evidence stays unknown.
  The 20% battery threshold affects presentation only, never smoke/alarm logic.
- Clear incident origins, pending explicit clearance, request types and recorded
  recovery; limited stored history is not presented as a complete event timeline.
- Corrected misleading configured state after a source identity change; reject
  conflicting battery units as percentages and tolerate malformed unit metadata.
- Improved EN/NL text, touch targets, wrapping and long-name dialogs. Navigation
  starts the chosen page at the top; live state updates preserve reading position.
- Ordinary reconnect preserves an open draft and blocks submission while offline.
  A full page/component reload is not promised to retain unsaved drafts.

## Verified checks and remaining limits

Local validation passed **450 backend tests**, **49 frontend tests**, Ruff/format,
hassfest, PowerShell, Compose and cleanup. Each exact HA version passed **25 runtime
and 16 driver checks**. All eight combinations of EN/NL, light/dark, phone 390x844
and tablet 1024x768 were visually inspected in the isolated simulator, including
setup, maintenance, long-name dialogs and incident details. See the
[review and coverage limits](https://github.com/Xat0X/AlarmMesh/blob/0.1.0-beta.5/docs/usability-review.md).
Hosted Actions must pass for the exact release commit before publication.

No detector, siren, phone delivery or physical self-test was tested. HA command
acceptance does not prove physical operation; cached data does not prove recent
radio contact or detector health. AlarmMesh depends on HA and connectivity and
does not replace independent smoke alarms or a certified fire alarm system.
