# AlarmMesh 0.1.0-beta.2 — Optional linked sounding

Opt-in test release for an existing Home Assistant installation. **Linking stays
off for existing beta.1 groups and for new groups.** Installing or opening the
panel does not enable linking or change detector settings. This installation
review must leave linking off; no physical activation is part of this release task.

## Before updating and rollback

1. Create a Home Assistant backup and keep its recovery information privately.
   Record the currently installed AlarmMesh version.
2. This version adds a new group-storage payload. Returning to beta.1 requires
   the matching pre-update HA configuration backup, not just older Python files.
3. In Marketplace, open AlarmMesh, enable **Pre-release** and select
   **0.1.0-beta.2** in the version/install dialog. Older HACS users select this
   beta through their version dialog. Repository-link updates may take time to
   appear; use the available refresh/check-update control if needed.
4. Install, restart Home Assistant as prompted, then refresh the browser.
5. Open AlarmMesh as an administrator. Inspect existing source selection,
   detector names, groups and both overview entities. Check that **Samen laten
   afgaan / Sound together** remains **Off**. Do not enable it or change linkage
   prerequisites during this installation check.

Source-folder installation is unchanged: no manual ZIP extraction or frontend
resource registration is needed. Minimum HA remains 2026.10.4. The tested versions
are exactly 2026.10.4 and 2026.11.1; this is not a claim for every HA version.

If an unreleased development build was deliberately configured with enabled
linking, its explicit configuration is retained. It is not equivalent to a
default-off beta.1 upgrade; review that configuration before restarting it.

## Included

- Administrator-only, explicit group mappings with model/provider validation,
  preview and acknowledgement before enabling. Existing source/status behavior,
  identities, branding and responsive EN/NL interface remain intact.
- Separate smoke origins and action outcomes, bounded calls, deduplication,
  independent target failures and cancellation on unload.
- Corrected per-target incident lifetime: a new incident in one group is not
  blocked by an unrelated still-active group.
- No notifications, test-all action or automatic detector-setting changes.

## Model/provider scope

| Model | Zigbee2MQTT | ZHA |
| --- | --- | --- |
| Heiman HS1SA-E-PLUS | Activation; restricted stop of its own automation sounder | Not confirmed |
| Aqara JY-GZ-01AQ / lumi.sensor_smoke.acn03 | Activation only; existing linkage prerequisite required; no mute/stop | Not confirmed |
| SMSZB-120 | One 60-second activation request, no renewal | Same through a verified existing siren entity |

Unknown models can remain smoke sources but are not guessed into sounder targets.
Aqara and SMSZB-120 are **activation-only**, not full automatic start/stop support.
Command acceptance does not confirm audible sound. See [profile and lifecycle
details](../linked-sounding.md).

## Validation and remaining limits

The release commit must pass hosted CI before publication: 323 backend tests,
15 frontend tests, Ruff, hassfest and 17 simulated compatibility scenarios on
each of HA 2026.10.4 and 2026.11.1. Action handlers/provider metadata are mocked;
actual MQTT/ZHA drivers, radios, audible activation, local-alarm separation and
physical recovery are not established. Existing-installation upgrade/rollback
acceptance for this payload remains an owner pilot.

Linking uses Home Assistant and its integrations; it is not direct radio linking
between detectors and cannot be relied on while those components are unavailable.
No smoke reported is not a safety guarantee. AlarmMesh is not a certified fire
alarm system and must not replace certified standalone smoke detectors.

Use [Marketplace release guidance](https://contributors.home-assistant.io/marketplace/guides/releases/)
for version selection. Report expected/actual behavior and the HA/AlarmMesh
versions; sanitize screenshots and never share tokens, backups or recovery keys.
