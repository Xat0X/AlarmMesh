# AlarmMesh 0.1.0-beta.3 — Device catalog and Bosch correction

**Linking remains off by default. Before updating, leave every group unlinked.**
Existing explicitly enabled groups retain their settings: switch them off in
AlarmMesh before this installation review if you previously enabled any. Do not
enable linking or change detector prerequisites during the installation check.
This release task does not install on your HA or trigger any real detector.

## Install and recover

1. Create a Home Assistant backup; keep its recovery information privately and
   record your installed AlarmMesh version.
2. Open Marketplace > AlarmMesh, enable **Pre-release** and choose
   **0.1.0-beta.3**. In older HACS, use the beta/version selection dialog.
3. Install, restart Home Assistant as prompted and refresh the browser.
4. Open AlarmMesh as an administrator. Check preserved source selection, names,
   groups and both overview entities. Keep **Samen laten afgaan / Sound together
   off**. Existing disabled groups and new groups stay disabled.
5. Inspect **Compatibility**, search/filter models/providers and inspect detector
   battery/fault/test information without starting an alarm or self-test.

Installation still uses the repository's normal integration folder, not a new
ZIP-installation route. Minimum HA remains **2026.10.4**; the tested versions are
exactly **2026.10.4** and **2026.11.1**. Other versions are not implied tested.

Retain the pre-update backup for recovery. Returning to beta.1 requires its
matching configuration backup because it cannot read the newer group payload.
For beta.2 recovery, a matching backup is also the conservative route; this
release does not claim a tested production rollback. Do not replace files and
assume changed configuration or mapping authority is automatically restored.

## Included

- Offline catalog of **52 canonical definitions / 67 model and variant rows**,
  with separate Zigbee2MQTT and ZHA assessments and searchable compatibility.
- **17 Zigbee2MQTT** and **10 conditional ZHA** definition-level activation
  contracts. This counts software contracts, not physically accepted devices.
- Additional Heiman, Aqara ZHA, IAS, Bosch and ShinaSystem profiles, using
  validated existing HA entities. Marketing aliases and shared Tuya model names
  do not automatically grant control authority.
- Read-only battery, device-problem, firmware and test information where HA
  provides it. A value's change time is not recent radio contact or health proof.
- Existing per-target incident handling, default-off groups, explicit admin
  confirmation, original smoke rules, identities, branding and EN/NL layouts.

## Bosch BSD-2 correction

BSD-2 is eligible only when its same-device, correctly bound `broadcast_alarms`
switch **explicitly reports off**. On, missing, disabled, unknown or unavailable
blocks configuration and execution. The condition is rechecked immediately
before dispatch, including after waiting for an execution slot.

AlarmMesh never changes that switch. Enabled broadcast can sound other BSD-2s
outside the confirmed target list. Older broader local BSD-2 assignments receive
a different profile fingerprint and require review, not silent reuse.

## Scope and limits

All new action profiles are activation-only unless the existing owned Heiman
PLUS MQTT stop contract applies. No generic mute/stop, notification, test-all
action, setting modification or direct device escape hatch is added.

Before publication the exact release commit must pass hosted checks: **367
backend tests, 20 frontend tests**, Ruff/hassfest and **20 runtime plus 14 driver
checks per HA version**. Driver checks use real HA MQTT discovery/actions with
synthetic local topics and offline ZHA code with mocked device I/O. They are not
a complete Zigbee2MQTT converter/radio chain or real ZHA pairing test.

Physical smoke sensing, audible activation, separation from local alarms and
device recovery remain **not tested**. A successful HA command is not proof of
audible sound. The website smoke filter also contains heat/acoustic/contact
proxies and dedicated sirens; catalog presence is not optical smoke detection.

AlarmMesh depends on HA, its integrations and connectivity. This is a pre-release,
not a certified fire alarm system or a replacement for standalone smoke alarms.
No smoke reported is not a safety guarantee.
