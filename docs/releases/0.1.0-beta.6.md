# AlarmMesh 0.1.0-beta.6 — Maintenance, action preview and HTTP self-test fix

Test release with opt-in maintenance phone messages, a read-only group action
preview and anonymized local diagnosis. Includes the HTTP/self-test confirmation
correction and reviewed Dutch/English phone/tablet presentation.

## Install with outputs disabled

1. Create a Home Assistant backup and retain the recovery information privately.
2. Before updating, switch off **Sound together / Samen laten afgaan** in any
   previously enabled group. Leave incident notifications and automatic scripts
   off during installation review. Existing explicit opt-ins are preserved.
3. In Marketplace/HACS, enable pre-release versions and select **0.1.0-beta.6**.
4. Install, restart Home Assistant and fully refresh the browser to load the new
   frontend. New groups and new maintenance automation remain off by default.
5. Inspect source selection, groups, Maintenance, Diagnosis and the group's
   **What happens during an alarm?** example. The example issues no commands.
   A physical self-test may produce sound; do not start it during installation review.

This release task did not install on or operate your existing Home Assistant.
The normal repository integration-folder installer route is unchanged. The
attached `alarmmesh.zip` is an integration-root archive for manual extraction into
`custom_components/alarmmesh/`, not into the HA configuration root.
Minimum HA remains **2026.10.4**. Exact tested versions: **2026.10.4** and
**2026.11.1**; no other version is implied tested.

For rollback, restore the pre-update backup together with its matching AlarmMesh
version. Replacing integration files alone does not reverse configuration/storage
changes. This release adds a separate versioned maintenance store; its receipts
must not be manually reset to force retries. No production rollback is claimed.

## HTTP/self-test correction

Confirmation IDs now use cryptographically secure random bytes available on local
HTTP, replacing secure-context-only `crypto.randomUUID()`. This fixes a reproduced
browser failure that could display a generic error before any request reached HA.
Request ownership, exact-target confirmation and server validation remain intact.
Missing secure randomness blocks submission with a specific browser message;
there is no weak random fallback or automatic retry. Duplicate warning text in
the test dialog is removed. This is not physical self-test validation.

## New functions and refinements

- **Maintenance messages:** separately enabled, no recipients selected by default,
  battery/problem/unavailability categories, 5/15/30/60-minute observation delays
  (default 15), optional confirmed recovery and bounded durable deduplication.
  Quiet startup avoids replay; invalid/unknown evidence is not false recovery.
  Receiver failures are isolated. Smoke processing never waits for maintenance.
- **Action example:** shared current execution conditions, disabled/blocked targets,
  notification recipients, script order and future recovery requirements. No
  incident, saved permission, device command or executable confirmation is created.
- **Diagnosis:** allowlisted snapshot with consistent aliases and local preview/copy.
  No raw names/IDs, network addresses, credentials, script contents or message bodies
  are exported. Nothing is uploaded automatically.
- **Presentation:** distinguish unassessed stop support for blocked preview targets
  from activation-only support, and label recovery receipts as recovery requests.

## Evidence and limits

Final local checks: **486 backend tests**, **57 frontend tests**, Ruff/format,
hassfest, PowerShell/Compose and cleanup PASS. Each exact HA version passed
**27 runtime and 16 isolated provider checks**. Eight EN/NL light/dark phone/tablet
combinations were visually inspected. The simulator's real five-minute waiting
period, mock receiver error isolation, recovery, diagnosis copy and reconnect draft
retention were exercised. Two final presentation regressions failed before fixes.
See [behavior and independent visual evidence](https://github.com/Xat0X/AlarmMesh/blob/0.1.0-beta.6/docs/maintenance-tools.md#independent-visual-follow-up).
Hosted Actions must pass on the exact release commit before publication.

Only mocks, synthetic inputs and isolated provider fixtures were operated. Real
detectors, sirens, phones, external scripts and the production installation were
not operated. HA acceptance is not evidence of audible sound or phone delivery;
cached values do not prove radio contact or detector health. Neither self-test nor
catalog membership establishes physical smoke-detection acceptance. AlarmMesh
depends on HA/connectivity and does not replace independent smoke alarms or a
certified fire alarm system.
